First signed user build (release-keys), bootloader relocked. Installed from the Mac
(m3max, macOS 27.0.1, Homebrew fastboot 37.0.1-15733141) with the site's install script.
Checks over adb from the Mac; boxes left blank are for the owner on the phone.

## Install

- Download: `husky-install-2026101318.zip` matches `SHA256SUMS-2026101318` and GitHub's asset
  digest; OTA zip digest matches too.
- `avb_pkmd.bin` in the zip = `65894abf…bf161` = the release-notes fingerprint = the public key
  inside `vbmeta.img` (compared byte for byte before locking).

  site's install script (patched, see below) flashed it again; lock done by hand afterwards.

## Failed

| U1 | **No Updater in the image**: no `app.grapheneos.updater` (`pm list packages -a`), no activity for `android.settings.SYSTEM_UPDATE_SETTINGS`. GrapheneOS adds it only with `OFFICIAL_BUILD=true` (`GrapheneOS/platform_build:target/product/media_system.mk:39-41` @ `90e8e1d7`); nothing in our build sets it, so the Updater fork is synced but not built | `export OFFICIAL_BUILD=true` for release builds; release gate: `app.grapheneos.updater` in the image before publishing |

Consequence of U1: 2026101318 can't update itself. Getting the next build onto this phone
(and any other on 2026101318) means `adb sideload` from recovery, or unlock (wipe) and
reinstall. The OTA test planned for the next build moves to the build after U1 is fixed.
