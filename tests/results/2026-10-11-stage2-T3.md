Build 8 (fork `envs-17` at `7187029c` "Reboot credential: harden storage, lifecycle and
dispatch", with `f554fde6`, `066afecc`). Script: `tests/stage2.sh`, which now checks every
result and prints PASS / FAIL.

| `lifecycle` | PASS: owner PIN changed to the reboot PIN → `deleted reboot credential, equal to the new owner credential`; unrelated change → kept; owner lock removed → `deleted reboot credential, owner screen lock removed`; no reboot from envB's prompt afterwards |

The first `lifecycle` run failed its two log checks only: the script read the `main` log
buffer, `Slog` writes to `system`. Fixed in the script and rerun; the functional checks (no
reboot afterwards) passed both times.

Side effect seen: each reboot-PIN entry at envB's prompt counts as a failed attempt for envB
(doc 04, Q5). After the runs above envB was throttled (`Request throttled`) until the timeout
ran out; a right entry clears the count.

T1 on the same build: stock locksettings tests unchanged (797 passed, the same 17 ignored and 8
assumption failures, `WeaverHidlBasedSyntheticPasswordTests` still doesn't load).
`AlternateCredentialsTests` 15/15 after one test-only fix (the owner's synthetic password has
to be initialised before enrolling a PIN in the harness; the first run failed all 14 tests that
enrol for that reason).

Duress regression (`tests/stage1.sh duress --yes-wipe`, reboot PIN enrolled): device gone
after 4 s and powered off (the emulator process ended). Booting the same disk without
`-wipe-data` didn't reach adb within 150 s (normal: 25 s). Emulator then reset with
`-wipe-data` and `stage1.sh setup`.
