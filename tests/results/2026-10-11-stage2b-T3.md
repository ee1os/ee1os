# Stage 2b: Reboot PIN screens in Settings, 2026-10-11

Build 15 (Settings fork `envs-17` with the new screens, frameworks/base with the review
fixes). `tests/stage2b.sh screens`, driven with uiautomator: PASS, 10/10. Owner PIN asked;
Add; duress PIN as reboot PIN → "same as the duress PIN or password" error, nothing saved;
valid PIN saved; Update to another PIN (the service then refuses that PIN as duress, so it
has it); Delete with confirmation; Add again (service has it).

Seen on the way, all script problems, fixed in the script:
- typing the owner PIN before the PIN pad has focus is lost: the script waits for it;
- saving closes both screens, as in the duress screens (the setup screen reports cancelled
  when it stops, and the main screen then finishes): the script reopens the screen;
- the action items sit below the long description and are outside the dump until scrolled.

Not covered (T4): how the screens look, keyboard behaviour, the no-lock, corrupt-record and
second-factor states, password type, rotation (the owner PIN is asked again).
