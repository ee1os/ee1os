### Item 3: system_server crash

```
*** FATAL EXCEPTION IN SYSTEM PROCESS: backup
java.lang.IllegalStateException: SharedPreferences in credential encrypted storage are not
available until after user (id 0) is unlocked
  at android.app.ContextImpl.credentialProtectedStorageCheck(ContextImpl.java:699)
  at com.android.server.backup.UserBackupPreferences.<init>(UserBackupPreferences.java:39)
  at com.android.server.backup.UserBackupManagerService.<init>(UserBackupManagerService.java:622)
  ...
  at com.android.server.backup.BackupManagerService$Lifecycle.lambda$onUserUnlocking$0(BackupManagerService.java:1882)
```

When envB unlocks, backup starts its per-user service (`BackupManagerService.java:1874-1884`).
That opens `backup_preferences` through the system context (`UserBackupManagerService.java:622`,
`UserBackupPreferences.java:37-41`), and `credentialProtectedStorageCheck` tests
`UserHandle.myUserId()`, which is 0 in system_server, not the user the file belongs to
(`ContextImpl.java:686-701`). With the owner still locked, any secondary unlock throws on the
backup thread and takes system_server down. Stock AOSP doesn't allow the switch at all;
`allow_user_switching_when_system_user_locked` does.

### Item 2: open files survive key removal

Every eviction logged `Files still open after removing key ... These files were not locked!`,
followed by vold retrying for about 100 s. One retry ended in `Waiting for files to close never
completed ... were not locked!`. `lsof` afterwards:

```
system_server 2102 /data/system_ce/10/accounts_ce.db
system_server 2102 /data/system_ce/10/accounts_ce.db-shm
system_server 2102 /data/system_ce/10/accounts_ce.db-wal
```

No envB processes were left. `AccountManagerService` did get `onUserStopped 10` and ran
`purgeUserData` (`AccountManagerService.java:185-187`, `:1581-1596`) 37 ms before
`fscrypt_lock_ce_storage 10`, but the CE database is attached to the DE connection
(`AccountsDb.java:1362`) and stays open. So after a stop, envB's account database stays
readable in kernel memory. Encrypted names in `ls` don't prove the whole CE is locked.
