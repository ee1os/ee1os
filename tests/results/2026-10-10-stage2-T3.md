# Stage 2: reboot credential on the emulator, 2026-10-10

Fork `frameworks/base` `envs-17` on top of `84183aff`. All builds report the same fingerprint,
so the commit is what identifies them:

- build 5: `ce54caed` + the reboot credential with a shell bug (`isNone()` on the zeroized
  credential after the call: the credential was saved, the shell then threw);
- build 6: `3de3688f` ("Add reboot credential", bug fixed) + `d34c6e71` (backup fix).

Script: `tests/stage2.sh`. Owner PIN 1111, envB 2222, duress 9999 / `duress-pw`, reboot PIN 5555.

| duress with reboot PIN enrolled | fires, device gone after 4 s (regression gate) |

Notes:

- The first build 5 run of `noop` is invalid: `adb shell` dropped the empty arguments, so the
  deletes never ran and all three timing rows had both alternates. The script passes `''` now.
- `am start-user -w 10` reports "could not start user" for envB with a PIN: `-w` waits for the
  unlock. The user is started (`RUNNING_LOCKED`); the verify that follows is what counts.
- Keyguard entry is T4 (by hand), as for duress: `input text` doesn't reach the bouncer.
